Atomica

A 2D particle simulator built in C# using MonoGame, because nothing screams "productive weekend" like simulating virtual dust specks being harassed around by gravity. Atomica lets you visualize basic Newtonian physics in real-time, with very intuitive controls (trust).

Features That Definitely Exist

  • Real-time 2D particle simulation (yep, things move)
  • Change gravity direction with the arrow keys (truly groundbreaking)
  • Toggle cursor-following mode, if you want the particles to chase your mouse like needy toddlers
  • Resizable window support (unless your machine says "no")
  • Built-in instructions rendered with System.Drawing because why not

How It Works

Atomica is powered by MonoGame, the framework of choice for people who enjoy writing their own physics engine instead of using Unity like a normal person. The particles follow basic Newtonian physics, meaning they accelerate due to gravity, bounce off walls, and sometimes just decide to ignore the laws of physics if your code is bad (oops).

Technologies: C#, MonoGame, System.Drawing

Controls

  • Arrow Keys: Change gravity direction. North? South? Your call.
  • Spacebar: Toggle whether the particles follow your cursor. It's like being a wizard, but with fewer consequences.
  • Esc: Quits the application (What more do you want).

Installation (No, It's Not On Steam)

Download the installation package from the repo's releases tab

Then run the .exe inside (If it doesn't work then please hesitate to contact me)

Why This Exists

  • It's fun to watch particles bounce around and pretend you're doing science.
  • You'll learn about MonoGame, physics
  • Makes a decent screensaver if you leave it running long enough (it doesn't).

Gorilla Warfare

A multiplayer FPS where everyone plays as a gorilla. It's technically functional and very low effort. Built in Unity over the course of a week, mostly to refresh my knowledge on Photon PUN networking.

Gameplay Summary

  • Multiplayer lobby system using Photon PUN
  • Host-controlled match starting
  • Custom room names and usernames
  • Basic FPS movement: WASD, Jump, Sprint, Shoot
  • Scoreboard tracking kills and deaths
  • Red bullet impact squares that vanish after 30 seconds, for realism
  • Gravity-enabled death via falling into the void
  • Permanent T-posing gorilla player models, for atmosphere

Technical Implementation

Created in Unity using Photon PUN for networked multiplayer. The lobby system supports room listing, joining, naming, and host-based game control. A somehwat goofy FPS controller manages player input and shooting. Enemies do not exist. Everyone is the same gorilla. There are no teams. No win condition. Only meaningless violence.

Technologies: Unity 2022.3, C#, Photon PUN 2, Unity Input System

Design Notes

The map consists of ramps and walls. There is a gun. It makes no sound, but you'll know it fired because a red square will appear briefly where the bullet hit. The T-posing gorillas are not placeholders. They are the vision.

Graphorama

Graphorama is a WPF-based function plotting application written in C#. It uses the OxyPlot library to graph mathematical expressions in real-time, with support for multiple simultaneous plots, axis adjustments, and basic input validation. It does exactly what you think it does... it draws lines based on equations. Not much more, not much less.

Functionality Overview

  • Plots mathematical functions using OxyPlot
  • Supports basic arithmetic, trig, logs, and exponentials
  • Multiple expressions can be plotted at once
  • Adjustable axis limits with live updates
  • Real-time graphing toggle with user-defined speed control
  • Input validation for malformed expressions

Technical Architecture

The application is built in C# using WPF for the user interface and OxyPlot for rendering. Expression parsing is handled internally, with basic safeguards to avoid runtime crashes when someone inevitably types "log()" with no arguments. The structure is straightforward: a text box, a graph, and some buttons. It does what it needs to.

Technologies: C#, WPF, OxyPlot, .NET 8.0

Real-Time Plotting

When real-time mode is enabled, functions are plotted progressively over time. This feature exists mostly to make the plotting experience feel more dynamic. Speed can be adjusted within a reasonable range. Values outside that range may break things. That's on you.

Input Format

Function inputs accept typical math expressions. Example syntax:

  • 2x + 3 - Linear
  • sin(x) - Trig
  • log(x) - Logarithmic
  • ArcTan(x) - Inverse trig (case-sensitive)
  • sqrt(x) - Square root

Syntax errors will prompt a warning message. Some functions are case-sensitive by design, which is either a technical limitation or a test of patience.

Graph Management

  • Update axis limits manually using X Min and X Max fields
  • Clear the graph with one button click
  • Select plotted functions from the list to delete
  • Zoom and pan with mouse input (assuming OxyPlot doesn't crash)

Sumo Robot (His name is pablo escrowbar)

A Bluetooth-controlled sumo robot that weighs 3.5kg (How is it still working) Built with an ESP32, a welded aluminum chassis, and a very funny 24V battery that almost set my schoolbag on fire (oops)

Hardware Summary

  • ESP32, because I like the unpredictable pairing issues
  • 24V battery pack (probably too much, but it works)
  • Two buck converters:
    • 12V → motor drivers
    • 5V → ESP32 (the brain, allegedly)
  • Two BTS7960 motor drivers, because if something's going to catch fire, it might as well be powerful
  • Two high torque, low speed motors mounted with "custom" welded brackets
  • Chassis made of aluminum sheets (Might have gotten scammed)
  • Front scooper welded at a 40° angle. It does not flex.

Control System

Controlled via Bluetooth using a generic app (keypad that sends integers and updates booleans) Range is adequate but it has pairing issues which make it a hassle to use competitively Also we might have ruined the battery like 4 times

Power Delivery

The 24V battery feeds into two buck converters. One drops to 12V to feed the motor drivers. The other drops to 5V to keep the ESP32 awake long enough to crash into things. No overcurrent protection. No fuse. Should have added something like that (oops).

Performance

  • Top speed: 3~ m/s
  • Pushing Force: 50N~
  • Bluetooth stability: works like 4 times out of 10

Testing Footage (Unreleased, for a reason)

Most testing consisted of ramming the robot into a box, a wall, and my own foot. Success was defined by whether the robot still turned on afterward. The robot did, in fact, not turn on for the first 10 tries. It took us a month and a funny loss in a competition due to battery failure to actually fix the robot.

Future Plans

  • Redesign the chassis with a heavier core in mind
  • Auto-targeting (read: guess and shove)
  • A flipper in the slope
  • A Battery that actually has a BMS
  • Custom App with commands (Like spinning cw or ccw, dashing, etc)
