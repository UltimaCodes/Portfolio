MACROFY

Turns a spare keyboard into a dedicated macro pad — no driver, no bloat

C# WPF Win32
Plug in any USB keyboard, point Macrofy at it, and every key on that specific keyboard stops typing and starts firing macros — launch apps, open URLs, type snippets, hotkeys, media control, run commands — while the keyboard you're actually typing on keeps working like nothing's different. Pitch, from my own README: "like a Stream Deck, except it's a whole keyboard and it's free."

The Actual Hard Part

This sounds simple until you try to build it. Windows Raw Input can tell you which physical keyboard sent a keystroke, but it can't block that keystroke from reaching whatever app has focus. The obvious fix — a low-level keyboard hook — can block keys just fine, but it's blind to device identity. And here's the part that actually breaks your afternoon: once you block a key at that level, Windows never generates the Raw Input event for it. You can't block a key and find out which keyboard it came from afterward. Blocking destroys the only evidence.

The fix was hooking WH_KEYBOARD instead of WH_KEYBOARD_LL — a message-based hook that fires after Raw Input has already logged the device, instead of before. Everything downstream (layers, per-device profiles, the whole macro engine) sits on top of that one correctly-ordered fact.

Features

  • Per-device profiles — different macro sets for different spare keyboards
  • Layers, so one keyboard can hold more macros than it has keys
  • Layout calibration ("Learn Keys") instead of hardcoding a keyboard layout
  • Tray integration, light/dark theme
  • Deliberately driver-free — a driver-based approach would risk getting flagged by anti-cheat (Vanguard/EAC/BattlEye), so this stays entirely in userspace
